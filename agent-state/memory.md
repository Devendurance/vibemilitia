# Memory

## Project facts

- Stack: Next.js 16.4.5 App Router, React 19, Tailwind v4, Phaser 4.2.1, TypeScript strict, Vitest 5.
- Multiplayer stack: Colyseus 0.18.10, `@colyseus/sdk` 0.18.9, `@colyseus/schema` 5.x, Node 24, `tsx` runtime dependency.
- Routes: `/` is P1 local mode. `/online` is the Colyseus lobby and match route.
- Game server: port `2567`, health at `/health`, lobby room `lobby`, match room `ffa`.
- Operator asset id: `viber-010`. Source: `public/brand/vibe_vibers_characters/vibe-vibers-viber-10.png`.
- Cutout: `public/sprites/viber-010/viber-010-cutout.png`, 728 x 962, binary alpha, 26.4 percent transparent.
- Original archived: `assets/source/vibe-vibers/viber-010-original.png`.
- Design system: `DESIGN.md`. Graphite `#16181C`, lime `#D7FF2E`, cream `#F5F3EC`, copper `#C7692F`, red `#E5484D`, sky `#9BD8F2`.
- Match: 90 seconds, score limit 10. Local has four combatants. Online has eight seats with bots filling unused seats.
- Player weapons: `vibe-rifle`, `scatter-blaster`, `vibe-lance`, plus online-only advanced weapons `akimbo-rifles`, `vibe-smg`, `heavy-cannon`, `rocket-launcher`.
- `PLAYER_WEAPONS` stays exactly three so P1 local mode never sees advanced gear. `ADVANCED_WEAPONS` holds the four online weapons and `ALL_PLAYER_WEAPONS` has all seven.
- Advanced tuning: Akimbo 36 shared rounds, 85 ms, 10 damage, 1800 ms reload, 11 px barrel separation; SMG 30 rounds, 70 ms, 8 damage, 1250 ms reload; Heavy Cannon 5 rounds, 900 ms, 60 damage, 2100 ms reload; Rocket Launcher 3 rounds, 1100 ms, 850 px/s, 180 px blast, 120 max to 40 min damage, 2400 ms reload.
- `PROJECTILE_CONFIG.maxActiveProjectiles = 220` bounds room-wide projectile growth.
- Local bots: `NULL-7`, `GLITCH-3`, `SCRAP-9`; 100 HP, 3-shot burst, 7 damage per round. Online rooms reuse the same bot definitions and add more callsigns.
- Validated online roster: `viber-010` (human default), `viber-006`, `viber-031`, `viber-123`, `viber-141`, `bureau-023`, `bureau-roll-01-07`, `bureau-roll-09-03`, `bureau-roll-25-07`, `bureau-roll-28-02`.
- Runtime manifest: `src/game/characters/roster.json`, generated by `python scripts/prepare_character.py --all`.
- Each skin has `/sprites/<skinId>/<skinId>-cutout.png`, a `character-<skinId>` Phaser texture key, an alpha-contrast preview, a game-scale preview, an avatar and a `cutout-report.json`.
- All ten sources are distinct single-character 1080x1080 renders. No composites or duplicate views were included.

## Multiplayer facts

- `src/game/multiplayer/GameSimulation.ts` is authoritative and headless. It owns humans, bots, projectiles, scoring, respawns, timer, rematch and events.
- `src/game/multiplayer/humanMovement.ts` is the shared AABB movement model used by the server and client prediction. It does not import Phaser.
- Server tick is 60 Hz. Snapshots broadcast at 20 Hz. Clients send input every 33 ms, capped at 45 messages per second.
- Clients send `{ seq, moveX, jump, jumpHeld, fire, reload, weapon, aim }` only. No positions or hit confirmations.
- Online snapshots include participants, projectiles, standings, feed, room metadata and `serverTickMs`.
- Prediction seeds from the first snapshot, steps every rendered frame, lightly corrects toward the authoritative position, and snaps on large errors.
- Remote humans and bots interpolate. Bullets extrapolate from their last snapshot velocity.
- `FFARoom.onAuth` rejects ended rooms with `MATCH_ENDED`. Colyseus returns a 522 on a full matchmake join and the client maps it to the full-room message.
- New rooms enter a countdown. Default is 10 seconds. Override with `MATCH_COUNTDOWN_MS`, clamped 0 to 60000.
- Countdown starts on the first human join. Humans can join during it. Bots fill empty seats only when the countdown expires. Eight humans start immediately.
- Combat input is ignored until the match phase is live.
- Quick Match uses `joinOrCreate("ffa", { open: true })`. The FFA handler uses `.filterBy(["open"]).sortBy({ clients: -1 }).enableRealtimeListing()`.
- Room metadata includes `open`, `joinable`, `phase`, `countdownMs` and `remainingMs`. `open` is false when the room is full or ended.
- `enableRealtimeListing()` is required for room cards to update after the lobby already exists.
- Bots fill rooms at countdown expiry. A later human removes one bot. A human disconnect creates one bot if below eight combatants.
- Online combatants use `CombatantView` and `PlayerVisuals` with the texture resolved from server snapshot `skinId`. Human default is `viber-010`. BOT labels are separate copper text objects.
- `GameSimulation` assigns bot skins from the validated roster with a room-seeded skin RNG plus an optional test seed. Bots avoid duplicate skins and skins occupied by humans when alternatives exist, keep their skin through death/respawn, and get a valid skin on backfill.
- P3A adds human skin selection. `JoinOptions.skinId` is validated in `FFARoom.onAuth` and again in `GameSimulation.addHuman`. Invalid IDs fall back to `viber-010`.
- The lobby uses a native radio fieldset for the ten-card picker, so arrow keys and focus behavior work natively. Selection is stored under `vibe-militia-skin`.
- The selected skin is sent through Quick Match, Create Room, Join Room and invite joins. It persists through death, respawn and replay and cannot be changed in a live session.
- The online HUD portrait, identity name and in-world sprite all use the selected skin.
- OnlineScene preloads all ten roster textures. The browser loads all ten even when a room uses eight.
- Bot snapshots use feet coordinates, like humans. Bot damage uses a `52 x 118` human-sized hitbox. Bot navigation and platform collision keep the original compact `56 x 36` movement body.
- Bot firing uses a Vibe Rifle presentation with the previous balance values: 7 damage, 900 projectile speed, 0.055 spread, 3-shot burst, 150 ms spacing and 1600 ms cycle. Bots that acquire an advanced weapon use the shared `stepWeapon`/`fireWeapon` path and the weapon's own cadence, ammo and reload.
- Bot aim and projectile origin are the character weapon pivot at `x + 28`, `feetY - 58`.
- Online `PlayerVisuals` is constructed with `{ dust: false }` because dust and hit-dust emitters are unused online. Local P1 keeps the full effects.
- Replay restarts the same room and keeps its humans. Everyone can click replay.
- `tsx` must stay in `dependencies` because `server:start` runs TypeScript directly.
- P3B-A adds server-owned medkit pickups. `src/game/core/pickups.ts` holds `MEDKIT_CONFIG` (50 HP, carry 2, 900 ms cooldown, 78 px radius, 20 s respawn) plus pure collection/respawn/heal rules.
- Sector 07 has 31 fixed `pickupSpawns` in `arena.ts`: 14 medkits, 3 contact, 3 frag, 3 stinking, 2 Vibe Lance, 2 Akimbo Rifles, 2 Vibe SMGs, 1 Heavy Cannon and 1 Rocket Launcher, on platform tops at least 60 px from spawn bodies.
- `GameSimulation` owns pickup state, validatates proximity and capacity, emits `pickup-collected`, `pickup-respawn` and `medkit-used`, and sends `pickups` plus per-combatant `medkits` in every snapshot.
- `OnlineInputPayload.useMedkit` is a request only. The server applies it on the next live tick, caps health, consumes one medkit and enforces a 900 ms cooldown. Duplicate/stale seq and full-health use are ignored.
- Pickups reset on first human join, match start, match end and rematch. Players lose carried medkits on death/respawn. Bots collect supplies and use medkits too.
- `InputController` exposes `medkitPressed` from H. The online HUD also has a clickable use button through the `use-medkit` bridge command.
- Online HUD fields include `medkits`, `maxMedkits`, `medkitFeedbackSeq` and `medkitFeedbackAmount`. The toast shows the authoritative healed amount.
- `verify:online:pickups` covers two-client pickup sync, collection, late join, independent rooms, respawn and live healing.
- P3B-B adds `src/game/core/grenades.ts` with contact, frag and stinking definitions, inventory helpers, blast damage and circle-rect collision.
- Grenade config: contact 180 max damage, 220 blast radius, impact detonation, 920 throw speed, 1500 gravity. Frag 120 max damage, 215 blast radius, 5000 ms fuse, 820 throw speed, 1400 gravity. Stinking 760 throw speed, 1400 gravity, 900 ms activation, 160 px cloud, 6000 ms duration. All use 700 ms throw cooldown, 64 active-entity cap, and 55 percent blast damage behind cover.
- `GameSimulation` owns `activeGrenades`, swept collision substeps, frag bounce/fuse, stinking bounce/activation, direct-hit damage, self-damage and cleanup. One explosion damages each combatant at most once.
- `OnlineInputPayload` adds `grenadeSlot` (0 contact, 1 frag, 2 stinking) and `throwGrenade`. Throws are edge-triggered with `throwRequestHeld`, sequence-guarded and cooldown-gated.
- Snapshots add `grenades`, `toxicClouds`, and per-combatant `grenadeContact`, `grenadeFrag`, `grenadeStinking`, `grenadeSelected` and `grenadeCooldownMs`. Events are `grenade-thrown`, `grenade-exploded`, `toxic-cloud-created` and `toxic-cloud-expired`.

- Toxic clouds use `STINKING_CLOUD_CONFIG`: 24 HP/s, 250 ms tick, 6 HP per tick, 160 px radius, 6 s life, max 24 clouds. One global `nextToxicDamageAtMs` tick with catch-up keeps damage stable across step sizes.
- Overlapping clouds apply one responsible cloud per tick. The closest cloud wins, with lower ID as the tie-breaker. Solid terrain fully blocks cloud damage. Cloud owner ID and name are stored for attribution after disconnect.
- Player self-eliminations increment deaths and add a feed entry, but do not increment the killer's eliminations. `lastKillerName` stays null for the death overlay.
- The HUD throwables panel has inline contact/frag/stinking SVG icons, three count badges, a selected state, a clickable throw control and cooldown status. The bridge commands are `select-grenade` and `throw-grenade`.
- Bots start with one of each grenade, 0 medkits, and server-owned cooldowns. They collect nearby supplies, seek medkits below 55 HP, use medkits, throw grenades on a 9 to 14 second decision cooldown with range/LoS gates, and apply a short local repulsion away from toxic clouds.

- `verify:online:stinking` covers three-slot HUD inventory, green cache art, cloud activation, 6 HP toxic ticks, self-elimination without credit, respawn loadout restoration, opponent toxic damage/elimination with owner credit, late-join cloud visibility and room isolation.
- `verify:online:grenade-perf` fills a room with 8 humans, throws all grenade types, creates dynamic loot through gated elimination hooks, and measures FPS, tick, active entities, peak loot, cloud overlap and snapshot size while a second room stays live.
- P3C-A adds `src/game/core/weaponInventory.ts` with `STARTER_WEAPON_LOADOUT = ["vibe-rifle", "scatter-blaster", null]`. Online humans own three slots. Slot selection is a 0-based index and the server ignores empty or unowned slots. Clients never send weapon IDs.

- Duplicate weapon pickup refills one full magazine. The target is the equipped copy if it owns that weapon, otherwise the lowest-ammo owned copy, then the lowest slot index on a tie. The refill never exceeds `magazineSize`.
- Full-loadout automatic weapon pickup is skipped and the loot remains active. `E` sends an edge-triggered `swapWeapon` request. The server replaces the equipped slot and scraps the old weapon, so no duplication is possible.
- `initState` / respawn restore the starter loadout, full rifle and scatter magazines, zero medkits, one of each grenade and slot 0. Default rifle bots keep `BOT_WEAPON` with id `vibe-rifle`; curious bots can replace it with an eligible advanced weapon.

Rockets use `ROCKET_CONFIG` (180 radius, 120 to 40 damage, 1.15 falloff, 0.55 cover) and shared `computeRadialDamage`, with one blast application per victim and no grenade consumption.

## P4 facts

- Touch input lives in `src/game/input/touchInput.ts`. `InputController` merges it into the same `ControlFrame` as keyboard and mouse. Touch controls render only on coarse pointers or `?touch=1`.
- Touch reset runs on `blur`, `orientationchange`, `visibilitychange`, `pointercancel` and lost pointer capture. Utility buttons send the existing bridge commands or queue one-shot actions.
- Audio lives in `src/game/audio/AudioEngine.ts`. It is original Web Audio synthesis, persists under `vibe-militia-audio`, has a 14-voice cap and one jetpack loop, and unlocks only after a gesture.
- Progression rules live in `src/game/progression/progression.ts` and cosmetics in `cosmetics.ts`. XP is settled server-side in `FFARoom.recordCompletedMatch` once per `match_id`.
- Guest tokens are `vm_guest_` plus 32 random bytes. Only the SHA-256 hash is stored. `POST /api/guest`, `GET /api/profile` and `PATCH /api/profile` are served by the Colyseus Express app.
- `ProfileStore` uses `node:sqlite`, WAL, foreign keys, `schema_migrations` and `VACUUM INTO` backups. The database path is `DATABASE_PATH`.
- `GameSimulation` snapshots now include `matchId`, `matchNumber`, and per-combatant `playerId`, `connected`, `level`, `badgeId`, `titleId`, `eliminationEffectId` and `trailId`.
- Reconnect uses Colyseus `allowReconnection` in `onDrop` with `RECONNECT_GRACE_SECONDS`. The SDK client `reconnection.minUptime` is set to 0 so a disconnect immediately after joining still reconnects. The client also caps retries at grace plus 2.5 seconds.
- `MAX_COMBATANTS` counts reserved disconnected humans through `simulation.humanSeats`. Reconnect does not add invulnerability and clears queued input.
- Verification hooks are still gated by `VIBE_MILITIA_TEST_HOOKS=1`. P4 adds `guardTarget`, `pauseBotLoot`, `disableBotCuriosity` usage in suites.
- Production config requires `ALLOWED_ORIGINS`, rejects wildcards, limits API bodies to 16 KB, rate-limits `/api` at 120/minute/IP and checks WebSocket upgrade origins.
- `npm run db:backup` writes a consistent SQLite copy with `VACUUM INTO`.

## UX overhaul facts

- `/` is the hub, not the local match. `/practice?difficulty=easy|normal|hard|merciless` is the local P1 fallback. `/online` is the focused lobby and live match.
- `RECONNECT_GRACE_SECONDS` defaults to 30 in `server/config.ts`. Production must set it to 30.
- Reload recovery is tab-scoped: `src/lib/resumeContext.ts` uses `sessionStorage`, never shared `localStorage`. `POST /api/resume` is bearer-authenticated, identity-bound, single-use and expiry-bound. The server keeps only SHA-256 hashes of 32-byte handles in `server/resumeRegistry.ts`.
- `server/resumeRegistry.ts` is process-local. A server restart loses live rooms and resume handles; guest profiles and leaderboard data persist.
- Schema v3 adds `players.x_handle`, `players.x_public`, `players.leaderboard_visible` and `idx_players_leaderboard`. Apply automatically on server start.
- `GET /api/leaderboard?limit=25` is public, read-only, opt-in and server-derived. `server/leaderboard.ts` maps rows to `LeaderboardEntry` with `xVerified: false`.
- Display names are editable and non-unique. X handles are self-declared and must never be shown as verified.
- Guest rate limit is 30/min/IP. API limit is still 120/min/IP.
- `server/loadEnv.ts` preserves shell env values over `.env.local`, so `DATABASE_URL=' ' DATABASE_PATH=...` safely selects SQLite.
- Practice difficulty lives in `BOT_DIFFICULTIES` in `src/game/config/gameplay.ts` and is consumed by `Drone`.
- Hub components live in `src/components/hub/`. First-visit onboarding is a modal on `/`; the `/online` first-visit guidance is a non-blocking inline banner.
- The root layout imports only `src/app/globals.css`. Appending to a second global CSS import caused Turbopack to serve only one sheet. All hub/online/touch CSS is in `globals.css`.
- Touch v2 classes are `tc-*`; old `.touch-*` CSS remains for any legacy fallback. TouchControls takes `variant`, `onExit` and `modeLabel`.
- Local practice has no grenades, medkits, advanced weapons or elimination loot. It uses the existing drone bots and supports the selected Viber cutout.
- `scripts/verify-hub-ux.mjs` (`npm run verify:ux`) captures the 10-size matrix and checks reload recovery. `SKIP_EXPIRY=1` skips the 30-second offline wait.

## P5 facts

- PostgreSQL is selected when `DATABASE_URL` is non-empty after trimming. SQLite is the fallback. Keep `DATABASE_URL` in the gitignored `.env.local`, never in source or logs.
- Dedicated Neon project: `vibe-militia`, PG 17, `aws-us-east-2`, production branch `main`, test branch `p5-test`. Pooled URLs are used for the server.
- `server/persistence/repository.ts` is the async contract. `SqliteProfileRepository` wraps `ProfileStore`; `PostgresProfileStore` owns the `pg` pool.
- PostgreSQL migrations are versioned. v1 covers `players`, `weapon_stats`, `matches`, `cosmetics` and `schema_migrations`. v2 adds `client_events`.
- Reward settlement uses `BEGIN`, `SELECT ... FOR UPDATE` on the player, duplicate check by `(match_id, player_id)`, stat updates and reward-delivery state in one transaction. The simulation loop never awaits database work.
- `FFARoom.queueMatchSettlement()` retries a failed settlement after five seconds. Reconnect reward delivery is awaited and failures are logged without leaking credentials.
- `server/db-migrate-postgres.ts` is non-destructive. It opens SQLite read-only, copies rows with `ON CONFLICT`, prints source and target counts and validates that target counts are not short. `scripts/create-migration-fixture.ts` builds a deterministic 2-player fixture.
- Touch settings live under `vibe-militia-touch`. `touchSettings.ts` clamps values and emits `vibe-touch-settings`; `TouchControls` listens so changes apply during a live match.
- `touchInput.ts` tracks separate `buttonFire`, `aimFire`, `buttonJumpHeld` and `thrustHeld` sources. `fire` and `jumpHeld` are derived so releasing one source cannot clear the other.
- The online Phaser config uses `Phaser.Scale.RESIZE` with `NO_CENTER`. Desktop `.game-frame` remains 1440x810. Mobile `.game-frame.is-touch` is fixed to `100vw` by `100dvh`.
- Portrait touch mode shows `orientation-guard` and hides touch controls. Fullscreen is requested on the `.game-frame` element.
- Feedback is anonymous. `client_events` stores kind, message, route, app version, optional guest ID and rating. It never stores IP or user agent.
- Client event rate limit is 20 per minute per session `clientId` sent in the JSON body. The session ID lives in `sessionStorage`, not a tracking cookie.
- CORS on the Colyseus Express app is owned by the transport and allows `Authorization` and `Content-Type`. Do not add a custom required header without testing preflight. This is why the feedback client ID is in the body, not `X-Client-Id`.
- `verify:online:p5` covers four landscape shapes, canvas/camera fit, control overlap, thumb reach, CDP multitouch, thrust, auto-fire, FIRE mode, touch settings streaming, feedback submission, portrait guard and desktop frame.
- P0-P4 browser suites are sensitive to stale rooms and short countdowns. Run matchmaking on a clean server. Run older suites with `MATCH_COUNTDOWN_MS=10000` and SQLite when host or Neon latency eats into their timing assumptions.
- The production Neon branch contains synthetic test profiles from this milestone. No real players exist yet. The `p5-test` branch is intentionally disposable and its PostgreSQL tests truncate `players`.



- Collision callback argument order can reverse when a group is paired with a sprite or array. Identify projectiles by their `bullet` data payload, never by argument position.
- `setTintFill(color)` is removed. Use `setTint(color).setTintMode(Phaser.TintModes.FILL)`.
- Static `Graphics` with hundreds of commands is expensive. Bake static layers with `generateTexture` and use images.
- Phaser graphics generated textures persist in the texture manager, so scene restarts should check `textures.exists`.
- Group `add` can reset body settings. Avoid adding pre-configured bodies to a physics group unless the settings are reapplied.
- Phaser 4 uses `this.add.particles(x, y, texture, config)` and emitter `emitting` booleans.
- Fast key taps can begin and end between frames. Buffer reload, jump, weapon and debug presses from `Key` down events instead of polling `JustDown` alone.
- Name pure supply helpers `applyMedkit`, not `useMedkit`. ESLint's `react-hooks/rules-of-hooks` treats the `use` prefix as a React hook inside class methods.

## Performance

- Always measure production, not the dev server.
- Headless Chrome can pace WebGL at 30 fps regardless of scene cost. Use `HEADED=1` for real gameplay frame rate.
- Production headed Chrome measured 56 to 60 fps at 1440 x 810 with one human and seven Viber bots. P3B-C clean runs measured 59 fps standard and 60 fps with 8 active toxic clouds.
- Server tick averaged 0.15 to 0.36 ms on clean P3B-C runs, with p95 0.27 to 1.10 ms. The grenade stress run measured 0.21 ms average, 0.27 ms p95 and 5.04 ms max with 8 peak grenades, 8 clouds, 8 humans and two concurrent rooms.
- Snapshot size with 23 pickups, 8 clouds and grenades in an eight-human room was about 14.5 KB at 20 Hz. Occasional max spikes are GC or scheduler noise. Restart the server before a clean perf measurement.
- P3C-A standard perf with one human and seven bots measured 57 fps, 0.28 ms average tick and 0.67 ms p95, close to the P3B-C baseline.
- P3C-A grenade and loot stress with 8 humans, 8 peak grenades, 7 clouds, 2 overlapping clouds, 9 peak loot entities, 25 pickups and two rooms measured 51 fps, 1.04 ms average tick, 0.65 ms p95 and a 15,460-byte snapshot. The P3B-C baseline was 60 fps, 0.21 ms average, 0.27 ms p95 and 14,471 bytes.
- P3C standard perf measured 58 to 59 fps, 0.22 ms average tick and 0.77 ms p95, 6/6 checks.
- P3C grenade, advanced weapon and loot stress with 8 humans, 31 advanced shots, 7 peak grenades, 7 clouds, 2 overlapping clouds, 10 peak loot entities, 31 pickups and two rooms measured 60 fps, 0.06 ms average tick, 0.15 ms p95 and a 16,319-byte snapshot, 15/15 checks.
- P4 standard perf measured 60 fps, 0.245 ms average tick and 0.547 ms p95 with audio active and a guest profile loaded.
- P4 stress measured 60 fps, 0.041 ms average tick, 0.128 ms p95, all four advanced weapons, 31 advanced shots, 8 peak grenades, 8 clouds, max overlap 8, 16 peak loot, 31 pickups and a 17,600-byte snapshot across two rooms.
- P4 snapshots grew about 8 percent over P3C because each combatant carries profile, level, badge, title, elimination and trail fields.
- P5 final clean headless perf measured 56 fps, 0.40 ms average server tick, 1.43 ms p95, 6/6 checks. An earlier run on a busy host measured 27.7 ms p95, so confirm host load before treating p95 as a regression.
- P5 P4 and P5 suites ran against the Neon test branch. Older P0-P4 browser suites ran against SQLite with a 10-second countdown to isolate gameplay from database latency.
- Machine load matters. Chrome and background agents can push the stress FPS into the 20s and server p95 above 16 ms. Confirm CPU load and restart the server before recording a number.
- Dev-server frame rate is not a valid performance signal. The Viber bot build measured 34 fps in dev and 60 fps in production.
- Static arena and background layers are baked. Local A* recomputes on an 850 ms cadence. Online bot repath uses `DRONE_CONFIG.repathMs`.

## Next.js gotchas

- `next build` must stay clean after adding server-only files. TypeScript checks `server/` through the root tsconfig.

## Production facts

- Frontend: `https://vibemilitia.vercel.app`, Vercel project `vibemilitia`, team `endy-s-winning-szn`, framework Next.js, Node 24.x, production branch `main`.
- Game server: `https://vibemilitia-game.endyos.xyz` on host `endy-vps` (`hermes.endyos.xyz`), user `endy`.
- systemd user units: `vibe-militia.service` (loopback `127.0.0.1:2767`) and `vibe-militia-tunnel.service` (Cloudflare named tunnel `vibe-militia-game`). Linger is enabled.
- Release layout: `~/apps/vibe-militia` symlink to `~/apps/vibe-militia-releases/<sha>`, env at `~/apps/vibe-militia.env` (0600), tunnel config at `~/.config/vibe-militia/tunnel.yml`.
- Port `2567` on that host belongs to another Colyseus service. Vibe Militia uses `2767` and never publishes it.
- `endy-vps` has no inbound 80/443 and no passwordless sudo. Public ingress is Cloudflare Tunnel only. Do not edit the shared cloudflared instance, the `chog-royale-*` units, or any Telegram and OpenBot services.
- Neon production branch `main` (`br-late-frog-behgzxyy`) is the only durable store. `p5-test` is disposable.
- `NEXT_PUBLIC_GAME_SERVER_URL` is set for Production only. Preview deployments fall back to `localhost` on purpose so they cannot reach the production backend.
- `MATCH_COUNTDOWN_MS=20000` in production because cold invite-link loads take 15-18 seconds.
- Desktop Playwright pages pause Phaser when hidden. Call `page.bringToFront()` before reading the online probe in a multi-page suite.
- Keyboard input reaches Phaser reliably only for the active page. `bringToFront` before movement assertions.

## Repo conventions

- No em dashes in prose.
- Preserve original NFT artwork. The game must never regenerate or restyle the character without a fidelity review.
- Keep game rules in `src/game/core`, AI navigation in `src/game/ai` and shared multiplayer rules in `src/game/multiplayer` free of Phaser imports.
- Commit and push meaningful checkpoints. `origin` is `https://github.com/Devendurance/vibemilitia.git` and `main` tracks `origin/main`.
