# Memory

## Project facts

- Stack: Next.js 16.4.5 App Router, React 19, Tailwind v4, Phaser 4.2.1, TypeScript strict, Vitest 5.
- Multiplayer stack: Colyseus 0.18.10, `@colyseus/sdk` 0.18.9, `@colyseus/schema` 5.x, Node 24, `tsx` runtime dependency.
- Routes: `/` is P1 local mode. `/online` is the Colyseus lobby and match route.
- Game server: port `2567`, health at `/health`, lobby room `lobby`, match room `ffa`.
- Operator asset id: `viber-010`. Source: `public/brand/vibe_vibers_characters/vibe-vibers-viber-10.png`.
- Cutout: `public/sprites/viber-010/viber-010-cutout.png`, 728 x 962, binary alpha, 26.4 percent transparent.
- Original archived: `assets/source/vibe-vibers/viber-010-original.png`.
- Design system: `DESIGN.md`. Graphite `#16181C`, lime `#D7FF2E`, cream `#F5F3EC`, copper `#C7692F`, red `#E5484D`, sky `#9BD8F2`.
- Match: 90 seconds, score limit 10. Local has four combatants. Online has eight seats with bots filling unused seats.
- Player weapons: `vibe-rifle`, `scatter-blaster`, `vibe-lance`.
- Local bots: `NULL-7`, `GLITCH-3`, `SCRAP-9`; 100 HP, 3-shot burst, 7 damage per round. Online rooms reuse the same bot definitions and add more callsigns.
- Validated online roster: `viber-010` (human default), `viber-006`, `viber-031`, `viber-123`, `viber-141`, `bureau-023`, `bureau-roll-01-07`, `bureau-roll-09-03`, `bureau-roll-25-07`, `bureau-roll-28-02`.
- Runtime manifest: `src/game/characters/roster.json`, generated by `python scripts/prepare_character.py --all`.
- Each skin has `/sprites/<skinId>/<skinId>-cutout.png`, a `character-<skinId>` Phaser texture key, an alpha-contrast preview, a game-scale preview, an avatar and a `cutout-report.json`.
- All ten sources are distinct single-character 1080x1080 renders. No composites or duplicate views were included.

## Multiplayer facts

- `src/game/multiplayer/GameSimulation.ts` is authoritative and headless. It owns humans, bots, projectiles, scoring, respawns, timer, rematch and events.
- `src/game/multiplayer/humanMovement.ts` is the shared AABB movement model used by the server and client prediction. It does not import Phaser.
- Server tick is 60 Hz. Snapshots broadcast at 20 Hz. Clients send input every 33 ms, capped at 45 messages per second.
- Clients send `{ seq, moveX, jump, jumpHeld, fire, reload, weapon, aim }` only. No positions or hit confirmations.
- Online snapshots include participants, projectiles, standings, feed, room metadata and `serverTickMs`.
- Prediction seeds from the first snapshot, steps every rendered frame, lightly corrects toward the authoritative position, and snaps on large errors.
- Remote humans and bots interpolate. Bullets extrapolate from their last snapshot velocity.
- `FFARoom.onAuth` rejects ended rooms with `MATCH_ENDED`. Colyseus returns a 522 on a full matchmake join and the client maps it to the full-room message.
- New rooms enter a countdown. Default is 10 seconds. Override with `MATCH_COUNTDOWN_MS`, clamped 0 to 60000.
- Countdown starts on the first human join. Humans can join during it. Bots fill empty seats only when the countdown expires. Eight humans start immediately.
- Combat input is ignored until the match phase is live.
- Quick Match uses `joinOrCreate("ffa", { open: true })`. The FFA handler uses `.filterBy(["open"]).sortBy({ clients: -1 }).enableRealtimeListing()`.
- Room metadata includes `open`, `joinable`, `phase`, `countdownMs` and `remainingMs`. `open` is false when the room is full or ended.
- `enableRealtimeListing()` is required for room cards to update after the lobby already exists.
- Bots fill rooms at countdown expiry. A later human removes one bot. A human disconnect creates one bot if below eight combatants.
- Online combatants use `CombatantView` and `PlayerVisuals` with the texture resolved from server snapshot `skinId`. Human default is `viber-010`. BOT labels are separate copper text objects.
- `GameSimulation` assigns bot skins from the validated roster with a room-seeded skin RNG plus an optional test seed. Bots avoid duplicate skins and skins occupied by humans when alternatives exist, keep their skin through death/respawn, and get a valid skin on backfill.
- P3A adds human skin selection. `JoinOptions.skinId` is validated in `FFARoom.onAuth` and again in `GameSimulation.addHuman`. Invalid IDs fall back to `viber-010`.
- The lobby uses a native radio fieldset for the ten-card picker, so arrow keys and focus behavior work natively. Selection is stored under `vibe-militia-skin`.
- The selected skin is sent through Quick Match, Create Room, Join Room and invite joins. It persists through death, respawn and replay and cannot be changed in a live session.
- The online HUD portrait, identity name and in-world sprite all use the selected skin.
- OnlineScene preloads all ten roster textures. The browser loads all ten even when a room uses eight.
- Bot snapshots use feet coordinates, like humans. Bot damage uses a `52 x 118` human-sized hitbox. Bot navigation and platform collision keep the original compact `56 x 36` movement body.
- Bot firing uses a Vibe Rifle presentation with the previous balance values: 7 damage, 900 projectile speed, 0.055 spread, 3-shot burst, 150 ms spacing and 1600 ms cycle.
- Bot aim and projectile origin are the character weapon pivot at `x + 28`, `feetY - 58`.
- Online `PlayerVisuals` is constructed with `{ dust: false }` because dust and hit-dust emitters are unused online. Local P1 keeps the full effects.
- Replay restarts the same room and keeps its humans. Everyone can click replay.
- `tsx` must stay in `dependencies` because `server:start` runs TypeScript directly.
- P3B-A adds server-owned medkit pickups. `src/game/core/pickups.ts` holds `MEDKIT_CONFIG` (50 HP, carry 2, 900 ms cooldown, 78 px radius, 20 s respawn) plus pure collection/respawn/heal rules.
- Sector 07 has 23 fixed `pickupSpawns` in `arena.ts`: 14 medkits, 3 contact, 3 frag and 3 stinking, on platform tops at least 60 px from spawn bodies.
- `GameSimulation` owns pickup state, validatates proximity and capacity, emits `pickup-collected`, `pickup-respawn` and `medkit-used`, and sends `pickups` plus per-combatant `medkits` in every snapshot.
- `OnlineInputPayload.useMedkit` is a request only. The server applies it on the next live tick, caps health, consumes one medkit and enforces a 900 ms cooldown. Duplicate/stale seq and full-health use are ignored.
- Pickups reset on first human join, match start, match end and rematch. Players lose carried medkits on death/respawn. Bots collect supplies and use medkits too.
- `InputController` exposes `medkitPressed` from H. The online HUD also has a clickable use button through the `use-medkit` bridge command.
- Online HUD fields include `medkits`, `maxMedkits`, `medkitFeedbackSeq` and `medkitFeedbackAmount`. The toast shows the authoritative healed amount.
- `verify:online:pickups` covers two-client pickup sync, collection, late join, independent rooms, respawn and live healing.
- P3B-B adds `src/game/core/grenades.ts` with contact, frag and stinking definitions, inventory helpers, blast damage and circle-rect collision.
- Grenade config: contact 180 max damage, 220 blast radius, impact detonation, 920 throw speed, 1500 gravity. Frag 120 max damage, 215 blast radius, 5000 ms fuse, 820 throw speed, 1400 gravity. Stinking 760 throw speed, 1400 gravity, 900 ms activation, 160 px cloud, 6000 ms duration. All use 700 ms throw cooldown, 64 active-entity cap, and 55 percent blast damage behind cover.
- `GameSimulation` owns `activeGrenades`, swept collision substeps, frag bounce/fuse, stinking bounce/activation, direct-hit damage, self-damage and cleanup. One explosion damages each combatant at most once.
- `OnlineInputPayload` adds `grenadeSlot` (0 contact, 1 frag, 2 stinking) and `throwGrenade`. Throws are edge-triggered with `throwRequestHeld`, sequence-guarded and cooldown-gated.
- Snapshots add `grenades`, `toxicClouds`, and per-combatant `grenadeContact`, `grenadeFrag`, `grenadeStinking`, `grenadeSelected` and `grenadeCooldownMs`. Events are `grenade-thrown`, `grenade-exploded`, `toxic-cloud-created` and `toxic-cloud-expired`.
- Human grenade inventory starts at one of each type, caps at three, and resets on death/respawn. Pickup types are `medkit`, `contact-grenade`, `frag-grenade` and `stinking-grenade`. Grenade pickups respawn in 22 seconds.
- Toxic clouds use `STINKING_CLOUD_CONFIG`: 24 HP/s, 250 ms tick, 6 HP per tick, 160 px radius, 6 s life, max 24 clouds. One global `nextToxicDamageAtMs` tick with catch-up keeps damage stable across step sizes.
- Overlapping clouds apply one responsible cloud per tick. The closest cloud wins, with lower ID as the tie-breaker. Solid terrain fully blocks cloud damage. Cloud owner ID and name are stored for attribution after disconnect.
- Player self-eliminations increment deaths and add a feed entry, but do not increment the killer's eliminations. `lastKillerName` stays null for the death overlay.
- The HUD throwables panel has inline contact/frag/stinking SVG icons, three count badges, a selected state, a clickable throw control and cooldown status. The bridge commands are `select-grenade` and `throw-grenade`.
- Bots start with one of each grenade, 0 medkits, and server-owned cooldowns. They collect nearby supplies, seek medkits below 55 HP, use medkits, throw grenades on a 9 to 14 second decision cooldown with range/LoS gates, and apply a short local repulsion away from toxic clouds.
- `verify:online:grenades` covers HUD inventory, selection, a shared frag fuse, five-second server fuse, warning visuals, a real contact-grenade bot elimination, kill-feed credit, medkit use and room isolation.
- `verify:online:stinking` covers three-slot HUD inventory, green cache art, cloud activation, 6 HP toxic ticks, self-elimination without credit, respawn loadout restoration, opponent toxic damage/elimination with owner credit, late-join cloud visibility and room isolation.
- `verify:online:grenade-perf` fills a room with 8 humans, throws all grenade types, and measures FPS, tick, active entities, cloud overlap and snapshot size while a second room stays live.

## Phaser 4 gotchas

- Collision callback argument order can reverse when a group is paired with a sprite or array. Identify projectiles by their `bullet` data payload, never by argument position.
- `setTintFill(color)` is removed. Use `setTint(color).setTintMode(Phaser.TintModes.FILL)`.
- Static `Graphics` with hundreds of commands is expensive. Bake static layers with `generateTexture` and use images.
- Phaser graphics generated textures persist in the texture manager, so scene restarts should check `textures.exists`.
- Group `add` can reset body settings. Avoid adding pre-configured bodies to a physics group unless the settings are reapplied.
- Phaser 4 uses `this.add.particles(x, y, texture, config)` and emitter `emitting` booleans.
- Fast key taps can begin and end between frames. Buffer reload, jump, weapon and debug presses from `Key` down events instead of polling `JustDown` alone.
- Name pure supply helpers `applyMedkit`, not `useMedkit`. ESLint's `react-hooks/rules-of-hooks` treats the `use` prefix as a React hook inside class methods.

## P1 systems

- Match timer and ranking are pure in `src/game/core/match.ts`.
- Safe respawn scoring is pure in `src/game/core/spawn.ts`.
- Bot pathfinding is pure in `src/game/ai/navigation.ts`, tested against the real arena.
- Bots collide with platforms and each other. Their thruster movement and paths are exposed in F1 debug.
- Scene restart drives replay. Reset match fields at the top of `ArenaScene.create`.
- Projectiles carry `ownerId`, `ownerKind`, `weaponId` and `weaponName`; bot bullets can damage other bots.
- `force-match-end` is a debug/test command used by the browser smoke test.

## Performance

- Always measure production, not the dev server.
- Headless Chrome can pace WebGL at 30 fps regardless of scene cost. Use `HEADED=1` for real gameplay frame rate.
- Production headed Chrome measured 56 to 60 fps at 1440 x 810 with one human and seven Viber bots. P3B-C clean runs measured 59 fps standard and 60 fps with 8 active toxic clouds.
- Server tick averaged 0.15 to 0.36 ms on clean P3B-C runs, with p95 0.27 to 1.10 ms. The grenade stress run measured 0.21 ms average, 0.27 ms p95 and 5.04 ms max with 8 peak grenades, 8 clouds, 8 humans and two concurrent rooms.
- Snapshot size with 23 pickups, 8 clouds and grenades in an eight-human room was about 14.5 KB at 20 Hz. Occasional max spikes are GC or scheduler noise. Restart the server before a clean perf measurement.
- Dev-server frame rate is not a valid performance signal. The Viber bot build measured 34 fps in dev and 60 fps in production.
- Static arena and background layers are baked. Local A* recomputes on an 850 ms cadence. Online bot repath uses `DRONE_CONFIG.repathMs`.

## Next.js gotchas

- `next/font/google` variable fonts cannot combine `axes` with fixed `weight`. Omit `weight` when using `axes: ["wdth"]`.
- `next dev` appends a "This is NOT the Next.js you know" block to `AGENTS.md`; keep it committed to avoid a dirty tree.
- Phaser is dynamically imported inside the client effect in `GameCanvas.tsx`, so SSR never evaluates it.
- `next build` must stay clean after adding server-only files. TypeScript checks `server/` through the root tsconfig.

## Repo conventions

- No em dashes in prose.
- Preserve original NFT artwork. The game must never regenerate or restyle the character without a fidelity review.
- Keep game rules in `src/game/core`, AI navigation in `src/game/ai` and shared multiplayer rules in `src/game/multiplayer` free of Phaser imports.
- Commit and push meaningful checkpoints. `origin` is `https://github.com/Devendurance/vibemilitia.git` and `main` tracks `origin/main`.
